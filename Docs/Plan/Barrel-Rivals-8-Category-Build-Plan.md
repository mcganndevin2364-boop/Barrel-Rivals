**Barrel Rivals — complete-product build plan**  
Engineering revision 6 · Gameplay revision 5 · Original 53 sections · Solo creator with AI-assisted development

This is the implementation plan for the complete Barrel Rivals game. It preserves the exact eight category ranges and 53 section titles. The [gameplay blueprint](Barrel-Rivals-Gameplay-Blueprint.md) defines player behavior and the [decision register](Barrel-Rivals-Design-Decisions.md) records choices. Gameplay revision 5 / engineering revision 6 adopts the user-approved [Reins Racing 0.5 plan](Reins-Racing-0.5-Implementation.md). It supersedes opt-in Lab, three-tap gate and third-person-intro defaults while preserving Classic and Reins v1 evidence and saved data. The earlier [ten-mechanic integration](Reins-Mechanics-Integration.md) remains context for retained mechanics, not authority over the new launch contract.

**Full product scope.** Reins Racing is the main game, first-person from the idle horse and walking alley through the finish. Live 1v1 turn-based competition leads; recorded challenges and simultaneous racing remain required. The full game includes ten distinct horses, horse/gear progression and customization, earned arena tiers, currencies, rewards and a premium store. Reins combines timed hold/release launch, rein steering, cadence, geometric pockets/kisses, Wrap, Dirt Read, Drive, bounded traits/bond/stamina, compatible ghosts and capped earned streak rewards. Classic is historical source/saves, not a required player-facing mode in the next build. Earned-only bonuses remain the working economy default, without loss of existing winnings or premium insurance; no live service or economy is implied.

**Current Reins boundary.** Implemented 0.4.0/build 4 still uses Reins v1 and three center-pad gate taps; the user played it and selected Reins. The approved 0.5 approach/release, forgiving tuning, first-person rider/art and v2 contracts are not implemented. Historical checks are 77 Editor, 8 Play Mode and 46 HTTP; measured device qualification remains open. Bounded horse parameters and own-best playback do not complete bonding, horse selection, rival gaps, streak rewards or online settlement.

**Execution standard.** For each section record intended behavior, files/assets changed, meaningful checks, observed results and remaining gaps. Use Planned → Implemented → Verified → Release-ready. A named class or a success message does not by itself pass a section. Keep source, metadata, package versions and build configurations reproducible. **Engineering execution.** Every section has a matching S01–S53 coding card in the [engineering playbook](Barrel-Rivals-Engineering-Playbook.md). CLIENT/CORE/CONTENT/ART/RENDER/NET/API/DB/PLATFORM/STORE/AUDIO/BUILD/OPS are defined in the playbook's stack register.

For each increment, use the correct language/tool for its layer, record actual dependency versions, wire the result into the running game and test the affected boundaries. Update both the section evidence and the relevant full-game requirement. Package, hosting and asset additions follow a demonstrated need and compatibility/cost check. The recommended backend is ASP.NET Core with PostgreSQL, to be validated at M1N before production adoption.

**Failure/settlement matrix.** Detailed values belong to versioned rules, but the economic outcomes must be unambiguous before public competition.

| Event | Race outcome | Economic behavior |
|---|---|---|
| Cancel before match start | No result | Release fee/item reservations. |
| Valid win/loss | Settle once | Publish the predetermined prize/trophy changes; one match item charge covers its runs. |
| Exact tie on underlying times | Draw | Refund entry stakes, no winner prize/trophy transfer; normal consumed match items stay consumed. No repeatable tie-reward farming. |
| Player timeout/forfeit or double player-caused DNF | Loss / double-loss | Apply the published failure policy; no automatic service-void refund and no prize for double-DNF. |
| Confirmed service failure | Void | Restore fees/items exactly once through auditable correction; no trophy loss. |
