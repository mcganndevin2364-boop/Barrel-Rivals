A sampled Terminal material points to URP’s Lit shader, which is present. These findings strongly support a missing active URP configuration as the cause of the magenta scene. A rendered verification is still required after repair.

Repair the sample project by restoring its original pipeline/renderer assets where possible, or creating compatible URP assets and assigning valid defaults and quality overrides. Sample-specific renderer features may also need restoration. Verify one material and scene before considering a bulk material conversion. Unity selects the active pipeline from Quality settings and the Graphics default, so merely installing the URP package is insufficient. [Unity’s pipeline configuration documentation](https://docs.unity3d.com/6000.1/Documentation/Manual/srp-setting-render-pipeline-asset.html).

For Barrel Rivals itself, create a small, dedicated URP arena scene in the canonical racing project. Repairing Terminal’s appearance does not add the racing systems to it.

**Multiplayer architecture decision.** Use a shared race simulation and scoring contract across the three modes. The production order is offline skill-loop practice, live turn-based duels with spectating, recorded challenges, then simultaneous duels. Revision 3 adds a small two-client timing/authority and independent-clock experiment immediately after the first skill loop, before content expansion. All three modes remain in the full product plan. The gameplay blueprint defines proposed equal-challenge reveal rules and independent slow-motion clocks needed for fair competition.

The repository’s Photon Fusion Host Mode choice needs reconsideration for a mobile release. Photon currently recommends Shared Mode for mobile in general and cautions that a player-hosted session inherits that player’s connectivity and cheating risks. Treat Fusion as a candidate, not a completed integration. Prototype session reliability and choose between Shared Mode with independent run verification and a dedicated authoritative simulation based on cost, fidelity, and competitive integrity. [Photon topology guidance](https://doc.photonengine.com/fusion/v2/fusion-choose).

Regardless of transport, the backend must own player identity, match/run IDs, legal loadouts, balances, and final rewards. For ranked times, validate inputs/course/timing against a versioned simulation or authoritative server; accepting an uploaded time or signed client summary is inadequate. Unity physics replay must not be assumed identical across devices. Keep presentation ghosts separate from competitive verification.

**Mobile publishing constraints already found.** Android and iOS Unity build-support modules are installed. The machine runs macOS 13.7.8; the selected developer tools are Command Line Tools, not a full Xcode installation. Apple currently requires Xcode 26+ and an iOS 26+ SDK for uploads; Xcode 26 requires macOS 15.6 or later. Plan a compatible Mac or hosted Mac build environment before depending on iOS release builds. This concerns the build computer, not the minimum iPhone OS the game must support. [Apple upload requirements](https://developer.apple.com/news/upcoming-requirements/), [Xcode system requirements](https://developer.apple.com/xcode/system-requirements).

Validate ARM64, native plugin compatibility, and 16 KB memory-page support in the actual Android artifact. Recheck submission requirements at release time. [Google Play target API requirements](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en), [Android page-size guidance](https://developer.android.com/guide/practices/page-sizes).
